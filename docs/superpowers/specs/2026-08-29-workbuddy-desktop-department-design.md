# WorkBuddy 桌面版部门创建设计

## 目标

让腾讯云代码助手 WorkBuddy 在本地工作区实现与 Codex 部门创建一致的使用效果：用户可以与 Agent 自由讨论部门设计，系统保存未定稿草案；只有用户在最终方案上明确确认后，才生成正式部门章程、任务规程索引、规程文件和能力计划。WorkBuddy 侧不部署飞书 Bridge，飞书或其他渠道由 WorkBuddy 自身负责。

## 平台文件映射

WorkBuddy 项目级记忆与 Skill 使用 `.codebuddy/` 目录：

- `CODEBUDDY.md`：工作区总入口，只放部门创建助手入口和已创建部门索引；
- `.codebuddy/skills/department-designer/SKILL.md`：自由对话、草案状态和最终确认流程；
- `.codebuddy/skills/<部门编号>-department/SKILL.md`：已确认部门的稳定章程、任务模式和审批边界；
- `.codebuddy/skills/<部门编号>-protocol-<规程编号>/SKILL.md`：单个任务规程，包含步骤、质量检查、交付物和完成条件；
- `.codebuddy/skills/`：除本工具生成的部门 Skill 外，只保存明确安装并通过验证的技能；
- `.workbuddy-department/<部门编号>/`：机器可读的 `department.json`、`workflow.json`、`manifest.json`、`memory.md`、`skills-plan.md` 和草案/事务记录。

`CODEBUDDY.md` 只保留索引和触发描述；规程正文分 Skill 保存，WorkBuddy 先根据 Skill 描述判断是否相关，命中后再读取对应正文。项目 Rules 会自动加载，因此不能用 Rules 存放所有规程正文。

## 交互状态机

1. **未开始**：用户表达创建部门意图，助手询问名称、目标、工作区和职责；不创建正式文件。
2. **设计中**：助手允许自由讨论和修改草案，接受新的任务类型、边界、规程和技能建议；每轮只保存草案快照，不写正式规则。
3. **待确认**：助手展示完整方案摘要、将创建的文件、能力安装计划和风险边界；提示只有明确的创建确认才会落盘。
4. **已确认**：仅识别“同意创建”“确认创建”“按这个方案创建”等明确语义。执行一次事务写入，生成正式文件并更新 `CODEBUDDY.md` 索引。
5. **已完成**：后续任务按四种模式处理：直接执行、单规程、组合规程、自由探索。新任务不强制命中已有规程。

普通“好的”“可以”“同意”可以接受上一条建议，但在待确认阶段不足以触发创建，除非用户同时明确指出“创建部门”。

## 章程内容

正式章程必须保留 Codex 版本已有规则：部门目标、职责、范围外事项、审批边界、任务模式、业务生命周期、编排策略、任务规程索引、Skill 主辅策略、能力安装状态和维护授权规则。任务规程不重复写入章程正文，只写编号、名称、触发意图和对应 Skill 路径。

## 事务和安全

- 工作区必须是存在的绝对普通目录，拒绝符号链接、用户目录根和 Bridge 状态目录；
- 部门编号必须稳定且安全，重复编号或已有标记时拒绝创建；
- 写入采用临时文件加原子替换；
- 任何一步失败都删除本次新增文件，保留草案快照和错误回执；
- 不把密钥写进 `CODEBUDDY.md`、规则、Manifest 或部门包；需要授权的技能保持待处理状态；
- 内部清单只声明本工具实际生成的 Skill 和工作区，不把待安装能力声明成可用 Skill，也不包含飞书聊天 ID 或路由配置。

## 接口边界

共享部门草案和校验逻辑沿用 `department-runtime`；新增 WorkBuddy 适配器只负责：

- 读取和保存 WorkBuddy 项目草案；
- 将已确认草案转换为 WorkBuddy 文件布局；
- 提供规则索引和单规程提取；
- 记录创建结果和错误回执。

适配器不负责 WorkBuddy 云端发布、飞书渠道配置、账号授权或模型调用。这样桌面版、企业智能体版和 Codex 版可以共享同一份部门规格，而不复制业务规则。

## 测试要求

- 自由对话和草案修改不会提前生成正式章程；
- 非明确创建确认不会执行落盘；
- 明确确认会生成 `CODEBUDDY.md`、章程 Skill、独立规程 Skill 和内部清单；
- 单规程读取不会加载其他规程正文；
- 断电/写入失败会回滚新增文件并保留回执；
- 生成文件符合 WorkBuddy 的 `.codebuddy/skills/<名称>/SKILL.md` 约定；
- 现有 Codex 部门测试和打包测试保持通过。
